BindCart 评审交付版 0.5.1

一、启动
请保留 BindCart 文件夹中的完整内容，在当前目录运行 Start 脚本，不要单独打开 HTML。
Windows 10/11 x64：双击 Start-Windows.cmd。
macOS 13.5+（Apple Silicon / Intel）：双击 Start-Mac.command。
若 Mac 脚本没有执行权限，在终端输入 bash 后拖入脚本，再回车。
启动后打开技术介绍页，点击“进入交互演示”。再次运行 Start 可重新打开当前会话。
停止服务：运行对应 Stop 脚本。仅关闭浏览器不会停止服务。

二、运行条件
完整交付包已包含 Node.js 24.19.0、锁定版本的运行依赖及网页资源。
核心商城、凭证认证和 TEST_USDC 本地测试付款不需要安装 Node、npm、Java，也不需要外部支付账号或互联网连接。
需要可写的存放目录、本机回环端口和现代 Chrome / Edge / Safari 浏览器。
Windows 推荐将 BindCart 放在较短路径下，例如 C:\BindCart。
测试方法见 app/README.md，测试结果见作品报告。

三、自检
Windows：双击 Check-Windows.cmd。
macOS：双击 Check-Mac.command。
自检先校验发布文件，再用独立临时账本运行完整购物付款、用户确认、重试、复制/撤销实验，以及普通/盲化两种模式的付款幂等测试。
自检不操作正在演示的订单，也不需要 Java。最终应显示 PASS；失败时保留终端输出。
Check 脚本覆盖文件校验和关键交付流程；全量回归方法见 app/README.md。

四、演示顺序
1. 浏览介绍页并进入交互演示，选择商品、加入购物车、前往结算。
2. 在控制台按“下一步”执行凭证签发、挑战、派生 VC、设备签名、联合证明、资格验证、提交授权申请。
3. 在商城核对并明确批准本笔付款，再回到控制台逐步同步授权、付款前复核、钱包签名、结算验证。
4. 收到成功回执后执行“核对商家并确认订单”。
5. 可查询原交易核对同一回执；开始新订单后可运行凭证复制与撤销实验。
商城界面沿用普通模式；普通与盲化两种算法的对比和幂等复现由 app/test、配套专项测试提供。

五、源码与状态
app/ 是实际运行的源码，不是另一个演示实现。源码开发说明见 app/README.md。
默认 npm start、npm run start:dual 与双击入口均启动同一主线。
当前主线使用独立 Node BLS 软件 eSIM；实现范围及测试结果见作品报告。
首次运行会在 app/var 创建本副本的订单、账本和会话状态。请勿将运行后的 app/var、日志或带权限的地址作为公开材料再次分发。
分发前保留一份未运行的提交材料副本；文件校验表不包含运行后生成的 app/var。

六、定位问题
提示 runtime missing：确认完整复制、文件未被安全软件隔离。
提示依赖不能加载：从完整提交材料重新复制 BindCart 文件夹；纯源码副本按 README 安装依赖。
端口或文件访问失败：将文件夹放到当前用户可写目录，保留 app/var/dual-error.log 排查。
挑战过期：在控制台明确获取新挑战。
付款结果待确认：查询原订单，保留账本，不通过删除状态或新建付款来消除提示。
